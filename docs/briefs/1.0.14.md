# Brief: Endless Space 1.0.14: reasons to buy, without nagging

Repo: `/home/user/endless`. Read `CLAUDE.md`, `docs/architecture.md`,
`docs/game.md`, `docs/server.md`, `docs/store.md`, `docs/analytics.md` and
`.claude/skills/android/SKILL.md` first, and follow their rules (commits, branches,
checks, migrations, comments, voice). Work on a branch from `main`, commit in
logical pieces that pass `npm run check`, run `npm run test:browser` after UI
changes, and fast-forward `main` at the end.

**Version:** versionCode 15, versionName "1.0.14". Update `package.json` /
`package-lock.json`, the what's-new lines and the release notes.

**Why:** 1.0.13 is live with credit packs, the short-of sheet and the end-screen
top-up line, but no one has bought anything yet. The store has had no reason to
buy *now*, and most players never see it. This release puts a reason to buy in
front of every player, in places they already look, and measures whether it works.

**Rules for every part:**
- No pop-ups on launch, nothing during a run, the countdown or the revive offer,
  and every offer has a plain "not now" or can be ignored.
- Unasked offers share 1.0.13's limit: at most one a session
  (`StorePrompts` in `src/economy/nudge.ts`). Cards in the title's row and badges
  on store items don't count as prompts; anything that opens over the screen does.
- Premium players see no ad offers. Purchases only exist in the Android app: on
  the web, offers point to the app or don't show.
- Every new offer logs through `platform/analytics.ts`: add its events to `Events`
  first (for example `offer_shown` / `offer_tapped` with the offer's id, and
  `view_store` with a new source for each way in).
- In-game text is lower-case, short and calm.

Build the parts in this order; each can ship on its own if a later one isn't ready.

## 1. A starter offer that runs out

- After a player's 3rd valid run (count from `progress.stats`), the title's card
  row shows a **starter pack** card: "pilot's starter pack · 47h left", with the
  cores, the nova hull, and a "best value" tag. Tapping it opens the store at the
  starter pack (`openStore(null, 'starter_offer')`).
- The 48 hours start the first time the card shows, by the server's clock
  (`server_now`, the game's `now()`), and the start is kept in the cloud save so a
  reinstall doesn't restart it. When the time is up, or the pack is owned, the card
  goes for good. The pack stays buyable in the store afterwards; only the card and
  its countdown go.
- Uses the existing `starter_pack` product: no new Play product.
- Once, ever: a player who saw it and let it run out never gets it again.

## 2. A store card on the title

- One card in the title's live-card row (with the daily challenge, goals and the
  pass) that rotates, picking the first that applies:
  1. the starter offer from part 1, while it runs;
  2. the season pass, when its premium track has rewards waiting ("4 premium rewards waiting");
  3. this week's best-value pack ("this week: 10,000 credits · best value"), the
     same for everyone in a week (by week key), alternating credits and cores.
- Tapping opens the store with a `view_store` source naming the card.
- It's a card, not a prompt: it doesn't use the session's one unasked prompt.
  Don't show it on the web build, and don't show it to a player in their first 2 runs.

## 3. First purchase doubled

- A player's first pack of credits or cores pays double. Every credit and core
  pack shows a "first purchase ×2" tag until then; the starter pack, the pass and
  premium don't double.
- Doubling happens on the server, so it can't be claimed twice: in
  `store_credit_purchase` and the cores path of `store_purchase_at` (a new
  migration with its `MADE` marker), double the amount when the account has no
  earlier non-refunded pack purchase in `store_events`. Do it in the same call
  that records the event, so a resent webhook event still pays once. Refunding a
  doubled pack takes back what it paid.
- The game knows whether the account has bought a pack from the server's records
  (as it already does for premium), so the tag goes away on every device.
- SQL tests: the first pack doubles; the second doesn't; a resent event pays once;
  a refunded first pack doesn't make the next one "first"; another player's purchase doesn't count.
- The purchase celebration says "first purchase: doubled".

## 4. Show premium looks at proud moments

- **After a new best** (not every run), the end screen shows one quiet line
  under the score, with the month's vault look on a small render of the
  player's ship: "this month's vault: <look> · 400 cores". Tapping it opens the
  hangar on that look, already on the ship to try. It uses the session's one
  unasked prompt; if that's gone, skip it.
- **In the hangar,** looks paid in cores (and the vault's) get a soft accent glow
  on their card and a "try it on" hint the first time a player opens that slot.
  Trying it on is what the hangar already does on a tap; this only points to it.

## 5. More from ads

- **Free cores for an ad, once a day:** in the store's cores section, a card
  "free · 5 cores · watch an ad", once a day (UTC day), as a rewarded ad
  (placement `free_cores`). Pay through `earn_cores` with the reason
  `adcores:<day>`; add the kind to `earn_cores` in a migration, at most 5 a day.
  Hidden for premium and on the web. Log it with the other ad events.
- **Interstitials, gently:** turn them on in `CONFIG.ads.interstitial` with the
  rules the code already has: not before the player's 3rd day, at most one every
  3 runs and every 3 minutes, never after a new best, never for premium, never in
  the first session of a day. Add an `interstitial_shown` event. Check the
  AdMob interstitial unit id is set (`VITE_ADMOB_INTERSTITIAL_ANDROID`) and list it in Tom's steps.

## 6. Sales Tom can schedule

- A `store_sales` table (new migration): product id, starts_at, ends_at, and a
  label (default "sale"). Readable by everyone through an RPC that returns only
  the sales running now (by the server's clock); written only from the dashboard.
- The store shows a "sale" tag on a product while its sale runs, and the title's
  store card (part 2) leads with it ("sale · 10,000 credits · ends in 2d").
- The price itself is Play's: Tom sets the discount in Play Console for the same
  dates. Write in `docs/store.md` how to run a sale: the Play Console promotion
  steps, then the row to add in Supabase's Table Editor.
- SQL test: only running sales come back; players can't write the table.
