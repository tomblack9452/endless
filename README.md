# Endless Space

A minimal 3D endless runner for phones. You steer a small ship across alien
ground, through canyons and asteroid belts, and down the rooms of a starship,
dodging everything in the way. It's built with Three.js, TypeScript and Vite,
and is set up for Capacitor packaging (app id `com.tomblack.endlessspace`).

Everything is procedural: the courses, the textures, the props, the sound
effects and the music. There are no image or audio files apart from the app
icons. The ship's interior is built from a pack of hand-made sections drawn
as text grids.

There's a light free-to-play layer on top: daily rewards and quests, a daily challenge with a streak, a daily shop of ship looks, a season pass and a premium currency
(cores). It all works on the device; a Supabase server and RevenueCat store
plug in behind it when their keys are set (see [docs/server.md](docs/server.md)).
Ranked groups pilots into leagues by ship power (upgrade points), so a ship
only races ships like it. Premium itself never makes a ship faster.

Play it at https://apps.tomblack.online/endless/.

How it plays, mode by mode and system by system, is in
[docs/game.md](docs/game.md).

## Running it

```bash
npm install
npm run dev
```

The dev server runs on port 5190 and listens on your network, so a phone on
the same Wi-Fi can open `http://<your-computer-ip>:5190`.

Phones only give motion sensor data (tilt steering) to secure pages. For that
there is an HTTPS server with a self-signed certificate on port 5191:

```bash
npm run dev:https
```

Accept the certificate warning once on the phone.

| Script | What it does |
|---|---|
| `npm run dev` | Dev server (HTTP, port 5190) |
| `npm run dev:https` | Dev server (HTTPS, port 5191) for tilt on phones |
| `npm run build` | Typecheck, then build into `dist/` |
| `npm run preview` | Serve the built `dist/` |
| `npm run typecheck` | TypeScript only |
| `npm test` | Fairness, collision, database and server tests (see [docs/development.md](docs/development.md#testing)) |
| `npm run db:setup` | Rebuild `supabase/setup.sql` from the migrations, and write `supabase/parts/` (the same in small pieces to paste; not committed) |
| `npm run db:apply` | Set up or update the Supabase database from your terminal (needs `SUPABASE_DB_URL`) |
| `npm run check-server` | Check the Supabase keys and database, and say what's missing |
| `npm run names:build` | Rebuild the pilot-name word list (`src/platform/nameWords.json`) from `scripts/name-filter/` |

Without a `.env` the game runs entirely on the device. To turn on the server,
purchases and ads, copy `.env.example` to `.env` and fill it in (it's never
committed); `npm run check-server` says what's missing.

`npm run dev` also adds a dev panel (start at any level, invincible,
autopilot, unlock all and more): see [docs/development.md](docs/development.md#dev-tools).

## Project layout

```
endless/
├── index.html            the page: every screen's markup
├── src/
│   ├── main.ts           entry point: fonts, styles, starts the game

│   ├── core/             the game loop and state machine, CONFIG, seeded RNG, storage, settings, dev panel

│   │   └── pieces/       the hand-made ship sections, drawn as text grids
│   ├── ship/             the player's ship: shapes, trails, looks and the catalogue, upgrades, hangar, ghost
│   ├── progression/      stats, ranks, leagues, goals and achievements, the daily challenge's streak, unlocks, seasons, the wallet
│   ├── economy/          daily rewards, weekly goals, the shop, the season pass and their screens
│   ├── ui/               screens and HUD (ui.ts, style.css), onboarding, tips, the tutorial, the goals and hangar views
│   ├── platform/         the device: input, haptics, share, reminders, feedback, back button, Google account, the name filter
│   ├── audio/            sound engine, synth helpers, generative music
│   ├── server/           Supabase or the device alone behind one interface: cloud save, the run outbox, boards
│   ├── store/            in-app purchases (RevenueCat) and what's owned for good
│   └── ads/              rewarded ads (AdMob) and their rules
├── tests/                Vitest: fairness, courses, collisions, the database (PGlite), economy, UI models
├── public/               icons, web manifest, service worker, store icons, privacy and support pages
├── supabase/
│   ├── migrations/       the database, one numbered file per change
│   ├── setup.sql         every migration in one file (generated by npm run db:setup)
│   └── functions/        the RevenueCat webhook (edge function)
├── scripts/              db:setup, db:apply, check-server, and the name-filter builder
├── android/              the Capacitor Android project
```

## Android

The app is the web build in a WebView (Capacitor 8). Always run Capacitor from
the project root:

```bash
npm run build              # typecheck and build into dist/
npx cap sync android       # copy dist/ and the plugins into android/
npx cap open android       # open Android Studio
```

- **On your phone:** Android Studio > Run. Leave `VITE_ADMOB_LIVE` unset so
  only Google's test ads show. Purchases only work in a build installed from
  Play.
- **A release:** raise `versionCode` (and `versionName`) in
  `android/app/build.gradle`, set `VITE_ADMOB_LIVE=1` for that build only,
  build and sync, then Build > Generate Signed App Bundle with the upload key.
  The bundle lands in `android/app/release/` for Play Console.
- The upload key (`.jks`) and `.env` never go in the repo.

The full steps are in [docs/store.md](docs/store.md#5-building-the-apps) (the
build, ads, Google sign-in) and [docs/play-console.md](docs/play-console.md)
(Play Console, from an empty account to launch and every update after).

## Server and store

Without keys, everything lives on the device. With them, Supabase keeps an
account per player, a cloud save, cores, the trusted clock and the
leaderboards; RevenueCat sells core packs, the season pass and premium in the
apps; AdMob shows rewarded ads in the apps. The web build sells nothing.

- What each does, and every Supabase dashboard setting: [docs/server.md](docs/server.md)
- Turning the leaderboards on, and changing the database: [docs/leaderboards.md](docs/leaderboards.md)
- Purchases, ads and Google sign-in setup: [docs/store.md](docs/store.md)

After adding a migration to `supabase/migrations/`, run `npm run db:setup`
(the tests check `setup.sql` is current) and `npm run db:apply` on the live
project.

## Deploying

Pushing to `main` runs `.github/workflows/deploy.yml`, which runs the tests,
builds, and publishes `dist/` to GitHub Pages. Other branches run
`.github/workflows/test.yml` (typecheck and tests). More in
[docs/development.md](docs/development.md#deploying).
